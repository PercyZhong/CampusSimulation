# 模型说明

## 0.2.0 开发状态

开发树加入合成辅导员资源名册、`mood` 内部变量、最终与初始压力差、离线同伴交流模板和本地工作台。辅导员不执行主体决策；离线模板不是 LLM。0.2.0 的规则实验、恢复和 Web 页面技术验收见 [独立记录](V020_ACCEPTANCE.md)；原有结果示例仍针对 0.1.0。新增规则和数值尚未校准，也未经过校园专业人员审阅。

## 用途与范围

本场景只用于探索合成群体在给定规则下的请求支持、服务等待、社交联结与压力变量变化。`stress`、`recovery`、`connection`、`willingness` 均为 0–1 的内部数值，不是临床量表。不能用于真实学生、个体风险排序、诊断或政策效果预测。

## 机制假设

- 每天一个外部学业负荷，按 `seed`、`academic_event` 和天数生成；初始人口与社交环网按独立命名流生成。
- 每个主体每天选择一个动作：参与课程、休息、同伴交流或请求支持。`request` 行动在写入时重新检查本人身份、已有请求、既有支持和开放时间。接受支持由有序队列与每日容量决定。
- 社交联系与压力按固定增减规则变化，并裁剪到 0–1。压力更新含每日 `0.15 × 当前压力` 的模型内适应项，防止持续工作负荷让所有主体机械地堆到上限；该系数未经经验校准。连续 7 天 `connection < 0.3` 是模型内群体计数规则，不表示个体健康阈值。
- `baseline` 为基准；`outreach` 在指定天数向所有合成主体显示一般信息；`easier_access` 将请求障碍乘以 0.45。三个条件服务容量相同；外部事件也相同。
- 规则智能体不请求网络或模型服务。行动与队列在 Society0 插件 SQL 中持久化，恢复使用已完成步骤。

## 输出解释与限制

等待均值只计入已成功服务的请求，未完成请求单列。分层按初始联结值机械划分，比例仅供模型内比较。没有经验数据校准，也没有校园专业人员参数审查记录。三次随机种子不足以推断显著性或现实因果效果；条件方向不能写成通过测试的保证。固定提交 `ca16f26` 的首轮 9 个 30 天实验在第 30 天全部得到压力 `1.0`，说明原增量规则存在上限堆积；该轮结果保留为模型失败模式，不作为条件比较依据。修正规则后的 Linux 技术验收已完成，详见 [Linux 集成验收记录](LINUX_ACCEPTANCE.md)；服务规则和参数仍待校园专业人员审阅及经验校准。
