# V063 阶段三：正式评估矩阵与固定比较协议

本阶段先固定比较协议，再运行付费模型矩阵。协议文件为 `configs/v063-evaluation-protocol.json`，协议 ID 为 `v063-formal-matrix-v1`。所有结果必须记录场景提交、Society0 提交、配置哈希和运行 ID；输出目录不得复用已有运行。

## 固定设计

| 因素 | 固定值 |
|---|---|
| 模拟时长 | 10 天，`start=1`、`end=10` |
| 人口 | 40 名学生、2 名工作人员 |
| 种子 | 11、22、33 |
| 政策条件 | `baseline`、`outreach`、`easier_access` |
| 规则驱动 | 离线规则，模型调用为 0 |
| Qwen 驱动 | `qwen-plus`，温度 0.2，上限 900 |
| DeepSeek 驱动 | `deepseek-chat`，温度 0.2，上限 900 |
| 提示词 | 当前 `peer-neutral-v2`；LLM 对话为 `peer-dialogue-v1` |
| 代码版本 | 每个矩阵批次使用同一个 scenario Git 提交 |

完整矩阵是 3 个驱动 × 3 个条件 × 3 个种子，共 27 次运行。规则运行用于确定性基线；两个付费模型分别运行相同的 9 个条件/种子组合。900 次上限覆盖 400 次每日决策、最多 400 次 `peer` 对话及有限重试；达到上限、API 错误或诊断失败的运行标为无效，不用其他运行替代。

输出目录遵循 `runs/v063-matrix-{driver}-{condition}-seed{seed}-10d`。例如：`runs/v063-matrix-deepseek-baseline-seed11-10d`。运行前保存协议文件的 SHA-256，并在报告中列出实际使用的模型 ID、温度和调用上限。

## 统计口径

每个运行先单独验收：完成 10 步、诊断错误为 0、学生数为 40、事件和每日事实完整、压力和情绪在 `[0,1]`。LLM 运行还须满足：每名学生每天有一条成功 `model_decision`；模型选择必须属于当天 `available_actions`；`peer` 完成事件的四轮文本、发言人顺序和 `backend=llm` 有效；`network_calls` 至少等于成功决策数加成功 LLM 对话数。

主要指标：求助率、支持率、已完成请求的平均等待天数、7 天低联结率、最终平均压力、最终平均情绪、五种行动的选择率和完成/拒绝率、`peer` 对话有效率、模型调用数。`accept_support` 的选择率从 `model_decision.detail.action` 统计；支持率只从最终学生状态和完成支持事件统计；未完成请求不进入等待均值。

比较采用配对描述统计：同一驱动、同一种子下比较政策条件；同一条件、同一种子下比较驱动。每个单元报告 3 个种子的均值、样本标准差和逐种子差值。只有 3 个种子，不进行显著性检验，不报告因果或现实效果结论；结果统一称为“未经校准的模型内情景结果”。

## 运行顺序

先运行 9 个规则基线，确认矩阵和导出格式；再分别运行 Qwen 和 DeepSeek 的 9 个单元。任何单元失败时保留失败目录和错误信息，修复后使用相同协议重新运行，不删除失败证据。矩阵汇总应从各目录的 `summary.json` 和 `events.jsonl` 自动生成，禁止手工抄录行动计数。

本协议不评价对话的临床、安全或现实有效性。对话质量只做结构和内容抽样检查：四轮交替、回应前文、使用状态/记忆、无诊断和虚假服务使用声明；人工评分规则需在下一阶段单独冻结。
