# V065 校园日历和课程约束

本阶段为每名学生、每天生成确定性的校园日历。日历提供课程、图书馆、食堂、社团与宿舍的场所、时段、开放状态和容量。五种学生行动保持不变；`attend` 继续表示到课，`rest` 在宿舍时段发生。

## 课程到场

- 周期中的前五天有课，周末课程关闭。到课占用该课程的上午时段及一个名额，容量为每门课程五人。
- 关闭、同一学生同一时段重复预约、课程名额已满分别产生 `course_closed`、`schedule_conflict`、`capacity_full` 拒绝原因。拒绝事件记录课程日历和申请时已占用名额。
- LLM 决策可读取日历和剩余名额；无课或无名额时 `attend` 从可用行动中移除。规则驱动在无课日不会选择 `attend`。最终容量仍由动作事务核查。
- 课堂接触继续只使用同日、同课程、先到场的学生。

## 轨迹评估

- 有课且未完成到课时，日终记录 `course_absence`，包括课程 ID、场所和连续缺课次数。无课日不生成缺课事件，也不清零连续缺课次数。
- `summary.json` 中的 `campus_environment_metrics` 统计到课、拒绝原因、课程场所使用、计划课程缺席和最长连续缺课。旧运行没有新事件时相应值为零；旧事件缺少日历时不推断实际预约。
- 图书馆、食堂、社团日历目前表示可用机会；没有对应到场行动时，不把开放状态解释为学生实际访问。历史实现把 `attend` 到课同时记为社团在场；该推断在本版停止，新运行只有专门的社团到场事实才能产生社团共同在场事件。

本阶段改变了学生可用行动与到课完成率，旧版 27 组评估矩阵只能作历史基线，不与新机制结果直接并表比较。日历与容量均为合成假设，不代表真实校园课表。
