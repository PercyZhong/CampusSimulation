# V063 阶段二：LLM 同伴对话与中性行动提示

行动提示词版本改为 `peer-neutral-v2`。保留 `peer` 是四轮对话的行动说明，删除“联结较低或近期没有同伴接触时应考虑 `peer`”的引导；不对任何行动设置配额。此前 `peer-context-v1` 的单次 Qwen 验收中，232/400 次决策选择了 `peer`，这说明需要检验提示词敏感性，不能据此判断新提示词下的分布。

LLM 驱动的运行在模型选择 `peer` 后，读取确定的同伴身份和双方状态，再由同一个提供商及模型生成四轮对话。要求双方按发起人、同伴、发起人、同伴交替发言；解析失败、发言人不符、文本为空或超长时使运行报错，不替换成离线模板。规则驱动继续使用可复现的离线语言层。

对话请求与行动决策共用 `max_model_calls` 上限。完成的 `peer` 事件记录 `backend=llm`、模型、提示词版本 `peer-dialogue-v1`、四轮文本及提供商用量；汇总的调用数计入这些完成事件。失败请求和 TLS 重试仍可能高于汇总数。10 天、40 名学生的决策需 400 次调用，若每次都选择 `peer` 则另需 400 次对话调用，应为可能的重试预留额度。

本地单元和集成测试用假响应验证对话结构、调用上限、事件和汇总；Linux 环境运行了 32 个通过的测试，Ruff 检查通过。

真实 Qwen `qwen-plus` 使用种子 11、40 名学生、10 天和 900 次调用上限运行，输出目录为 `runs/v063-qwen-neutral-dialogue-seed11-10d`，场景版本为 `f6ca204`。运行完成 10 步，诊断错误为 0。400 次模型决策中没有完成的 `peer` 行动；行动计数为 `attend` 220、`rest` 144、`request` 29、`accept_support` 完成 4 次及拒绝 3 次。汇总记录 400 次网络和付费模型调用，因此本次未触发对话生成，不能作为真实模型四轮对话的验收。最终有 29 人求助、4 人获得支持、25 人仍待处理；平均情绪为 0.6941562，低联结 7 天人数为 13。

此前 `peer-context-v1` 的一次同种子运行有 232 次 `peer`，而这次中性提示词运行是 0 次。这显示两次运行的行动分布差异很大，但 LLM 输出可能波动，单次对比不能确定提示词变化的因果效应；真实对话生成仍需出现 `peer` 的运行进一步验收。
