# V064：校园互动环境与行为轨迹

本阶段面向功能真实性扩展，不接入真实人工数据，也不改变参数校准方式。目标是让学生行动发生在可观察的校园环境中，并让行为轨迹能够被复核。

## 已实现的第一步

- 每名学生每天获得确定性的课程上下文：`course_id`、`venue`、`section`；上下文由种子、日期和学生 ID 生成，因此同一协议可复现且不同学生可以处于不同课程/场所。
- `course` 信息现在同时包含当天 `academic_load` 和该学生的课程上下文，LLM 决策可读取这些字段。
- 学生完成 `attend` 时生成 `class_attendance` 互动记录，保存日期、学生、同学、课程和场所；同学获得很小的联结更新，形成可追踪的课堂接触。第一步的同学从全体学生中抽取，尚未约束当天共同到场。
- `attend` 完成事件记录课程上下文和确定的同学，便于从 `events.jsonl` 重建行动轨迹。
- 汇总增加轨迹指标：行动切换次数、发生过互动的不同同伴数、课堂互动次数。

## 已实现的第二步

- 连续五名学生组成一个合成课程小组；同组当天共享课程、场所与班级，课程随日期轮换。课程编排是模型规则，不代表真实课表。
- `attend` 只可接触当天已到场且课程上下文相同的同学；找不到时记录 `classmate: null`。事件的 `contact_rule` 标明新规则，便于区分旧运行。
- 汇总按学生分别排列决策或行动，再计算行动切换次数，避免把不同学生之间的相邻日志误计为一次切换。新规则的课堂接触还会检查对象是否在同一天更早到场、课程是否一致；旧运行仍可重算。

## 已实现的第三步

- 同一天、同课程的第三名学生到场时，环境生成一次三人 `study_group` 事件，记录三名参与者、课程上下文及触发规则；其他人后来到场不会重复触发同一个小组。
- 小组事件是到场产生的环境互动，不是新的学生行动选项，也不调用模型。汇总新增 `study_group_events`，并核验三位参与者在事件之前均已到场且课程一致。

## 已实现的第四步

- 从事件日志逐学生计算五种行动的转移矩阵、最长连续相同行动长度；规则运行读取行动结果，LLM 运行读取 `model_decision`，因此拒绝的选择仍留在选择轨迹中。不同学生之间不构成转移。
- 已完成的 `peer` 事件按无向学生对统计不同关系数、重复接触次数及重复接触占比；没有接触时比率为 `null`。
- `summary.json` 增加这些轨迹指标；`matrix-report` 从既有 `events.jsonl` 重算每个运行的轨迹，并汇总每组的转移矩阵和指标，不要求重跑已有的 27 组实验。行为轨迹指标是描述性统计，不能单独证明机制真实性。

## 已实现的第五步

- 将已完成的 `peer`、课堂接触及三人小组共同在场转成无向学生对，统计各来源的接触次数、不同关系数，以及所有来源合并后的不同关系数。同一对学生可同时出现在多个来源，因此分项不同关系数不能相加当作总数。
- 按事件顺序计算每日新增关系与重复接触；同日重复接触也算重复。小组共同在场只表示三人同场，不等同于每一对都发生了真实对话。
- 单次运行的 `summary.json` 保存每日变化；正式矩阵报告从旧事件日志重算可得的 `peer` 和课堂接触。旧运行没有小组事件时小组来源为零，不能据此比较新旧机制的效果。

## 已实现的第六步

- 以每名学生首次完成的 `request` 和首次完成的 `accept_support` 为锚点，分别统计请求前、请求后与获得支持后三天的行动选择。锚点当天排除在窗口外；LLM 运行使用决策记录，规则运行使用行动尝试，因而拒绝的选择仍可观察。
- 每个窗口只纳入前后完整覆盖三天的学生；观察期不足的学生单独计入 `censored_students`，不作为零行动样本。报告保存各行动计数和合格人数，可从既有事件日志重算，无须调用模型。
- 这些是描述性的时间相邻轨迹，不能把支持后的行动变化解释为服务的因果效果；旧运行的 `summary.json` 不自动改写，新增字段在重新导出或重建矩阵报告时出现。

## 已实现的第七步

- 从已完成的 `attend` 事件计算每名学生的到课天数、记录到课程上下文的次数，以及不同课程和场所数；汇总同时给出总体人数与不同课程、场所数。场所数表示日志中的到课暴露，不代表学生在其他时间没有去过该场所。
- 对缺少 `context` 的历史到课事件单独计数；若没有可用的课程上下文，不同课程和场所数为 `null`，避免把未知误报成零。矩阵报告直接读取现有事件日志，不需要重新实验。

## 已实现的第八步

- 新运行在每日结算后为每名学生记录 `student_state` 事件，保存日期、压力、心情、联结和是否已获得支持；它是状态快照，不是学生主动行动，也不增加模型调用。
- 以首次完成的 `accept_support` 当日结算状态为起点，比较三天后同一学生的结算状态，报告压力、心情和联结的平均变化，并分别列出完整观察、期末截断及快照缺失人数。旧运行没有学生级快照时变化为 `null`，不会从总体均值推断个体恢复。
- 这一变化仅描述模型内部的时间轨迹，不能解释为服务效果；新旧机制的结果也不能直接混合比较。

## 已实现的第九步

- `export` 从权威 `campus_events` 生成 `interactions.jsonl`，统一保存日期、事件序号、发起者、参与对象、场所、回应和结果。包含已完成或因无同伴关系而拒绝的 `peer`、到课、三人小组同场、已交付服务及工作人员跟进。
- `peer` 四轮文本仍保存在 `events.jsonl`；互动视图只标明已记录对话。课堂接触和小组同场没有学生回应数据，明确标为 `not_recorded`；`service:main` 是服务端点标识，不是虚构的具体工作人员。
- 旧运行可在重新执行 `export` 后获得这一派生文件；现有 `matrix-report` 仍只读取 `summary.json` 和 `events.jsonl`。

## 已实现的第十步

- 新运行按当日登记的工作人员班次和每人剩余名额，为已完成的 `accept_support` 与 `staff_follow_up` 分配 `staff_id`；原有每日服务总容量仍然生效。统一互动视图以该 ID 表示服务接触对象。
- 旧事件没有 `staff_id` 时，统一互动视图继续使用 `service:main` 服务端点标识，不臆造工作人员。分配只表示模型中的名额归属，不代表已经模拟工作人员与学生的真实谈话或回应。

## 已实现的第十一步

- 每三名学生共享一个合成宿舍场所。学生完成 `rest` 时记录当天在场；若同宿舍室友已在当天记录到场，事件列出这些室友，统一互动视图将其标为共同在场，网络统计也单列 `residence_copresence` 来源。
- 宿舍共同在场不表示双方发生对话或同意互动，`response` 仍为 `not_recorded`。旧运行没有宿舍在场记录时该来源为零；同伴对话的伙伴接受或拒绝仍未作为独立决策实现。

## 行为轨迹评估方向

## 第十三步：同伴回应可审计字段
- 完成的 `peer` 事件记录 `partner_response` 和 `response_basis`，区分对话发起、伙伴回应和判定依据。
- 当前合成规则中，存在同伴关系边且四轮对话完成时记录为 `accepted`；这表示模型内的互动结果，不代表真实学生回应。
- 旧事件没有这些字段时，统一互动记录返回 `not_recorded`，保持历史运行兼容。

## 第十四步：独立伙伴回应
- `peer` 先生成 `peer_invitation`，再由伙伴状态和确定性随机流生成独立的 `peer_response`：`accepted`、`rejected` 或 `timeout`。
- 只有 `accepted` 才生成四轮对话并更新双方状态；拒绝和超时保留原因，不产生对话反馈。
- 互动导出同时保留邀请、回应和对话三类记录，可计算邀请接受率与对话完成率。

## 第十五步：关系形成与衰减
- 潜在同伴边保留在 `campus_edges`；实际接受的 `peer` 会在 `campus_relationships` 中记录关系强度、首次接触日、最近接触日和接触次数。
- 首次接受形成关系，重复接受增强关系；连续未接触的关系在每日结算中按天衰减，并记录 `relationship_decay_updates`。
- 关系边现在按稳定校园上下文分类为 `roommate`、`club_member`、`study_partner` 或 `acquaintance`；分类写入 `campus_relationships.relationship_type`，并附在邀请、回应和完成对话事件中。
- 不同关系类型使用不同的初始强度、重复接触增量、回应可用性加成和衰减速率；汇总新增 `relationship_type_counts`。
- 汇总增加首次形成次数、重复接触次数和平均关系强度，区分候选关系与实际互动关系。

## 第十二步：学生社团共同在场
- 每五名学生稳定属于一个合成社团，并共享一个学生中心场所；归属由学生 ID 生成，跨天可复现。
- 学生完成 `attend` 时登记社团到场。当天先到场的同社团成员会触发 `club_copresence`，记录参与者、社团和场所。
- 社团共同在场只是可观察的共同出现，不表示对话、回应或同意互动；统一互动记录的 `response` 为 `not_recorded`。
- 互动网络新增 `club_copresence` 来源，并与课程、学习小组、宿舍共同在场分开统计；不增加学生行动选项，也不改变既有比较协议。

后续可在新运行中继续扩展更长时间的状态轨迹。每项指标都以事件日志为来源，并保留日期和主体 ID，避免只比较最终均值。

## 下一步功能增量

1. 增加社团等其他互动场景，并区分主动发起、被动接触和拒绝。
2. 为同伴对话补充伙伴独立回应与拒绝机制，再扩展统一互动视图。

这些扩展仍属于合成校园模型；真实性来自更完整的可观察机制和轨迹，而不是对现实学生行为的校准声明。
