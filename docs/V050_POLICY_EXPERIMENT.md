# 0.5.0 政策机制实验说明

0.4.0 的 Qwen 单种子、5 天对照中，三个条件均有 40/40 学生请求支持，12/40 获得支持，已完成服务的平均等待为 2.5 天。该轮显示 LLM 决策已发生，但政策差异没有传导到这些汇总指标；三个条件尚无多种子或 30 天 LLM 验收。

0.5.0 将政策的公开信息和当日可选行动作为 `policy` 对象送给模型，并随 `model_decision` 事件记录。基线按原门槛计算求助机会；`easier_access` 将有效门槛乘以 0.45；`outreach` 在第 5 天一般信息实际发布后增加 0.16 的求助机会倾向。在信息发布前，学生收到的 `policy` 对象与基线相同，不会提前得知未来干预。机会按相同种子、日期和学生 ID 的命名随机流生成，便于条件配对。已有请求和已获得支持的学生不会再次开放 `request`；有待处理请求时开放 `accept_support`。模型仍可在当天其他可用行动中选择。公开机会只是未经校准的模型假设，不表示真实校园的服务资格或个体风险。

实验者可配置模型温度，默认 0.2。温度为零也不能保证提供商跨次输出完全相同。比较条件时应使用相同模型、温度、学生初始种子和模拟天数，保存每次配置、事件与用量。为避免过早声称政策有效，先做两天冒烟和多种子短期对照，再决定是否投入 30 天、3×3 的付费调用。`outreach` 信息从第 5 天送达，只能从当日起观察其可能影响。

本版本尚待 Linux 测试及真实 API 验收。结果只能解释为未经校准的模型内情景，不能用于真实学生的个体风险判断或校园政策效果预测。
