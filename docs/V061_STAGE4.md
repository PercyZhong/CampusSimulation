# V061 阶段四：跟进占用工作人员容量

`staff_follow_up` 现在在每日服务行动结束后执行。当天有工作人员值班且支持服务尚未用满名额时，到期跟进按学生 ID 顺序占用剩余名额；没有名额则保持待跟进状态，在后续有名额的日子再处理。跟进每名学生只完成一次。

支持服务使用量仍单独记录在 `campus_service_usage`，跟进使用量记录在 `campus_follow_up_usage`。每日事实新增 `follow_ups_today`，导出时验证 `served_today + follow_ups_today <= available_slots`。跟进不能挤占已经完成的支持服务；本阶段以支持服务优先。这是明确的模拟调度假设，并非真实校园规则。

集成测试覆盖：到期日的名额已被支持服务占满时延期；次日有值班和空余名额时完成；事件、学生记忆和名额记账只写入一次。

本改动改变启用跟进时的行为，因此阶段三的 10 天结果只适用于此前不受容量约束的实现。三个正式政策配置仍关闭跟进，其原有行为不变。Linux 测试和离线冒烟验收完成后在此补充结果。
